# Data Dictionary — UK Regional GVA Data Warehouse

## 1. Overview

This document describes the data structures, column definitions and relationships used in the UK Regional Gross Value Added (GVA) Data Warehouse.

The project analyses regional economic output using Office for National Statistics (ONS) data covering **1998–2023**.

The data warehouse follows a three-layer Medallion Architecture:

- **Bronze:** Raw ingested data.
- **Silver:** Cleaned and standardised data.
- **Gold:** Dimensional data model optimised for reporting and analytics.

The primary economic measure is GVA expressed in millions of pounds sterling (£m).

---

## 2. Data Source

**Provider:** Office for National Statistics (ONS)

**Dataset:** UK Regional Gross Value Added (GVA)

**Reporting period:** 1998–2023

**Geographic scope:** UK regional and aggregate geographic classifications represented in the source.

**Industry classification:** Standard Industrial Classification 2007 (SIC07).

The prepared analytical dataset contains:

| Attribute | Value |
|---|---|
| Records | 44,928 |
| Geographic entities | 16 |
| SIC07 industry codes | 108 |
| Reporting years | 26 |
| Earliest year | 1998 |
| Latest year | 2023 |

These figures describe the prepared dataset used in this project rather than the complete ONS source publication.

## 3. Bronze Layer

### Table: `bronze.RegionalGVA_Raw`

**Purpose:** Store source observations ingested into SQL Server before warehouse transformations.

| Column | SQL data type | Description |
|---|---|---|
| ITLCode | VARCHAR(30) | Geographic classification code |
| RegionName | NVARCHAR(200) | Geographic entity name |
| GeographyLevel | VARCHAR(50) | Geographic hierarchy classification |
| SIC07Code | VARCHAR(30) | Industry classification code |
| SIC07Description | NVARCHAR(500) | Industry description |
| IndustryLevel | VARCHAR(50) | Industry hierarchy classification |
| Year | INT | Reporting year |
| GVAMillionGBP | DECIMAL(18,2) | Gross Value Added in £ millions |

The Bronze layer preserves the prepared input dataset for downstream processing.

---

## 4. Silver Layer

### Table: `silver.RegionalGVA_Clean`

**Purpose:** Store validated and standardised regional GVA observations.

The Silver layer uses the same eight business columns as the Bronze layer.

### Transformations

- Standardisation of text values.
- Validation of reporting years.
- Validation of required fields.
- Detection and removal of duplicate business keys.
- Validation of numeric GVA values.
- Batch-based loading to manage SQL Server memory constraints.

### Business Key

The expected unique observation is identified by:

`ITLCode + SIC07Code + Year`

Each combination represents one regional industry observation for a reporting year.

---

## 5. Gold Layer — Dimensional Model

The Gold layer contains three dimension tables and one fact table.

### 5.1 `gold.DimRegion`

**Purpose:** Describe geographic entities.

| Column | SQL data type | Description |
|---|---|---|
| RegionKey | INT | Surrogate primary key |
| ITLCode | VARCHAR(30) | Unique geographic business code |
| RegionName | NVARCHAR(200) | Geographic name |
| GeographyLevel | VARCHAR(50) | Geographic hierarchy level |

**Primary key:** `RegionKey`

**Business key:** `ITLCode`

### 5.2 `gold.DimIndustry`

**Purpose:** Describe SIC07 industry classifications.

| Column | SQL data type | Description |
|---|---|---|
| IndustryKey | INT | Surrogate primary key |
| SIC07Code | VARCHAR(30) | Unique SIC07 business code |
| SIC07Description | NVARCHAR(500) | Industry description |
| IndustryLevel | VARCHAR(50) | Industry classification level |

**Primary key:** `IndustryKey`

**Business key:** `SIC07Code`

Industry hierarchy categories include TOTAL, SECTOR, SECTION, SUBSECTION, DIVISION and SPECIAL.

### 5.3 `gold.DimDate`

**Purpose:** Support reporting-year filtering and historical analysis.

| Column | SQL data type | Description |
|---|---|---|
| DateKey | INT | Surrogate primary key |
| Year | INT | Reporting year |

**Primary key:** `DateKey`

**Business key:** `Year`

The reporting period covers 1998–2023.

### 5.4 `gold.FactRegionalGVA`

**Purpose:** Store numerical GVA observations linked to the dimension tables.

| Column | SQL data type | Description |
|---|---|---|
| GVAKey | BIGINT | Surrogate primary key |
| RegionKey | INT | Foreign key to DimRegion |
| IndustryKey | INT | Foreign key to DimIndustry |
| DateKey | INT | Foreign key to DimDate |
| GVAMillionGBP | DECIMAL(18,2) | GVA amount in £ millions |

**Primary key:** `GVAKey`

**Foreign keys:** `RegionKey`, `IndustryKey`, `DateKey`

**Fact grain:** One observation per geographic code, industry code and reporting year.

---

## 6. Star Schema Relationships

| Dimension table | Fact table key | Relationship |
|---|---|---|
| DimRegion | RegionKey | One-to-many |
| DimIndustry | IndustryKey | One-to-many |
| DimDate | DateKey | One-to-many |

The fact table is positioned at the centre of the dimensional model.

This structure supports efficient filtering and analytical calculations in Power BI.

## 7. Business Measures

| Measure | Definition | Unit |
|---|---|---|
| Total GVA | Sum of selected GVA observations | £m |
| GVA in Billions | Total GVA divided by 1,000 | £bn |
| Previous Year GVA | GVA for the preceding reporting year | £m |
| YoY GVA Change | Current GVA minus previous-year GVA | £m |
| YoY Growth | Annual GVA change divided by previous-year GVA | % |
| COVID Impact | GVA change between 2019 and 2020 | % |
| Recovery vs 2019 | GVA change between 2019 and 2022 | % |

All aggregations must use appropriate geographic and industry hierarchy filters.

## 8. Data Quality Rules

The warehouse implements or documents checks for:

1. Missing business keys and required attributes.
2. Duplicate region-industry-year observations.
3. Reporting years outside 1998–2023.
4. Invalid numeric values.
5. Missing dimension references.
6. Silver-to-Gold record and value reconciliation.
7. Consistency of geographic and industry classifications.

Validation queries are available in `sql/07_validation.sql`.

---

## 9. Aggregation Considerations

The source contains multiple geographic and industry hierarchy levels.

For example, summing overall industry totals together with their constituent industry divisions would double count economic activity.

Similarly, geographic aggregates should not be summed together with the regions they contain.

For accurate Power BI reporting:

- Use a consistent geographic level for regional comparisons.
- Use a consistent industry classification level for industry comparisons.
- Select the appropriate overall-GVA industry code for headline economic totals.
- Verify that selected geographic entities do not overlap.

These controls help prevent inflated totals and misleading analytical results.
