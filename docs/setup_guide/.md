# Project Setup Guide

## UK Regional GVA Data Warehouse & Power BI Analytics

This guide explains how to set up the development environment and reproduce the UK Regional GVA analytical data warehouse.

## 1. Prerequisites

The following tools are required:

- Microsoft SQL Server
- SQL Server Management Studio (SSMS)
- Python 3.10 or later
- Pandas
- Microsoft Power BI Desktop
- Git

## 2. Clone the Repository

Open a terminal and run:

```bash
git clone https://github.com/sastry-hash/uk-regional-gva-data-warehouse.git

cd uk-regional-gva-data-warehouse
```

## 3. Configure Python

Create a virtual environment:

```bash
python -m venv .venv
```

Activate it on Windows:

```powershell
.venv\Scripts\Activate.ps1
```

Install dependencies:

```bash
pip install -r requirements.txt
```

## 4. Prepare the Source Dataset

Obtain the appropriate Regional Gross Value Added dataset from the Office for National Statistics.

The Python preparation script expects a CSV file at:

`data/regional_gva_cleaned.csv`

The input file must already contain these columns:

- ITLCode
- RegionName
- GeographyLevel
- SIC07Code
- SIC07Description
- IndustryLevel
- Year
- GVAMillionGBP

Run:

```bash
python python/01_prepare_data.py
```

The script validates the prepared dataset and exports:

`data/processed/regional_gva_cleaned_pipe.csv`

**Important:** The repository's current preparation script assumes the source data has already been transformed into the required eight-column structure. Any additional transformation from the original ONS workbook must be performed separately.

## 5. Configure SQL Server

Open SQL Server Management Studio and connect to your SQL Server instance.

Run the following scripts in order:

| Order | Script | Purpose |
|---|---|---|
| 1 | `01_database_setup.sql` | Create database and schemas |
| 2 | `02_bronze_load.sql` | Load prepared source data |
| 3 | `03_silver_transform.sql` | Clean and standardise records |
| 4 | `04_gold_star_schema.sql` | Build dimensional model |
| 5 | `05_reporting_views.sql` | Create analytical reporting views |
| 6 | `06_stored_procedure_indexes.sql` | Add stored procedure and indexes |
| 7 | `07_validation.sql` | Validate warehouse data |

All SQL scripts are located in the `sql/` directory.

Before executing `02_bronze_load.sql`, update the bulk-import file path to the actual location of the prepared pipe-delimited CSV file.

SQL Server must have permission to access that file.

## 6. Validate the Data Warehouse

Run:

`sql/07_validation.sql`

Review:

- Bronze, Silver and Gold record counts.
- Missing values.
- Duplicate business keys.
- Reporting-year coverage.
- Dimension relationships.
- Silver-to-Gold value reconciliation.
- Industry and geographic hierarchy classifications.

For the prepared project dataset, the expected reporting period is 1998–2023, with 44,928 observations.

Any discrepancies should be investigated before connecting the warehouse to Power BI.

## 7. Connect Power BI

Open Power BI Desktop.

Select:

**Home → Get Data → SQL Server**

Enter your SQL Server instance and database.

Example development environment:

- Server: `SAI\SQLEXPRESS`
- Database: `UK_Regional_GVA_DW`

Import the Gold-layer tables:

- `gold.DimRegion`
- `gold.DimIndustry`
- `gold.DimDate`
- `gold.FactRegionalGVA`

The SQL Server instance name is environment-specific and must be replaced when reproducing the project elsewhere.

## 8. Configure Relationships

Create the following one-to-many relationships:

- DimRegion[RegionKey] → FactRegionalGVA[RegionKey]
- DimIndustry[IndustryKey] → FactRegionalGVA[IndustryKey]
- DimDate[DateKey] → FactRegionalGVA[DateKey]

Use single-direction filtering from dimensions to the fact table.

## 9. Create DAX Measures

Refer to:

`powerbi/measures.dax`

Create the documented measures individually in Power BI.

Ensure that the table names match the imported semantic model and that percentage measures are formatted correctly.

## 10. Build the Dashboard

The reporting solution contains three analytical pages:

1. Regional Overview
2. Industry Performance
3. COVID-19 Impact and Recovery

Refer to `powerbi/README.md` for visualisation and reporting documentation.

## 11. Data Validation Considerations

The dataset contains overlapping industry and geographic hierarchy levels.

Use appropriate filters when calculating economic totals to avoid double counting.

Validate headline GVA values against the corresponding ONS source definitions.

## 12. Reproducibility Notes

This repository documents the project's data warehouse structure, analytical SQL scripts, Python preparation workflow and Power BI reporting logic.

Full end-to-end reproduction requires the prepared source dataset or an additional transformation process for the original ONS source files.

The repository is intended as an independent technical portfolio project rather than a production deployment.
